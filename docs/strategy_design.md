# 策略层设计图（由旧 codeflow/*.json 整理而来）

> 这是 2026-09-26 之前对 `strategy/` 的**设想**，当时对应一套"逐笔在线学习"的代码（已不存在）。
> 现在的实现路线改成了"固定栅格 + 决策树"（见 `strategy/features.py`），
> 但下面的分工和风控思路仍然是目标结构，留作参考。行号引用已失效，删去。

## 总图：一笔行情进来，到一张单发出去

```
 行情快照 ──► features.py ──► model.py ──► signal.py ──► risk.py ──► 下单
             算特征          出预测        定目标仓位     六道闸门
             (预热不够停)    (样本不够停)  (说"持有"停)  (任一不过拒单)
 ├─ 回测和实盘共用 ──────────────────────────┤  ├─ 只有实盘走 ─┤
```

- `strategy/` 里四个文件**互不 import**，由外面的 `live/runner.py`（实盘）和 `backtest/engine.py`（回测）串起来。
- 大部分行情走不到最右边：特征预热没完、模型样本没到、信号说"持有"，任一条都提前结束。
- **风控不在回测里**：回测只用前三个文件，`risk.py` 只有实盘的 executor 会调。
- 模型是边预测边学的：每一帧的对错要等 horizon 之后才知道，所以 `model.py` 同时做"回补旧答案"和"出新预测"。

## 1. features.py：一笔行情怎么变成一组特征

输入：一笔行情快照（盘口 + 最新成交）。

1. 中间价是 0 或负 → 返回空。
2. 盘口和上一笔比：买方抬价或加量记正，卖方反过来记正（OFI 增量，第一笔记 0）。
3. 只有真出现新成交才记主动买卖量，按"价+量"判是不是同一笔，不重复算。
4. 记中间价和相对上一笔的对数收益（bps）。
5. 记住这笔盘口，留给下一笔比。
6. 最短窗口没填满 → 还在预热，返回空（数据已存，只是不出特征）。
7. 一档买卖量失衡；微观价格偏离中间价（量大的一侧价格权重低）。
8. 最近 50 笔的订单流净额和成交流净额，除以总量压到 −1～1；加前 5 档失衡和价差。
9. 每个窗口各算一份收益之和、收益标准差（不足 2 笔记 0）。

输出：一包按名字取的特征，连同中间价和时间戳（FeatureState）。

## 2. model.py：一帧特征怎么出预测、怎么学

输入：这一帧的特征向量和当时的中间价。

1. 每个特征在线记均值方差（Welford），按它标准化，截到 ±8；不满 2 样本一律给 0。
2. 回头看：20 笔之前那一帧的真实收益现在已知 → 算一次误差，改一次权重，学习率随样本数衰减。
3. 记账：误差滑动平均、方向猜对次数（真实收益近 0 的不算）。
4. 把这一帧存起来，等 20 笔后再判对错。

输出：用现在的权重预测"未来 20 笔中间价会变多少（bps）"。

## 3. signal.py：预测值进来，仓位往哪走

输入：预测收益（bps）、当前价差（bps）、中间价。

1. 开仓门槛 = 两次手续费 + 一次价差 + 一点余量；盖不住来回成本就不动。
2. 有仓位就把持仓笔数加一。
3. 拿了 600 笔还没平 → 超时强制平仓（免得预测失效还一直拿着）。
4. 预测反向且超过门槛 → 直接反手（多翻空 / 空翻多）。
5. 预测衰减到退出带以内（退出带比开仓门槛窄得多）→ 平掉现有仓位。
6. 空仓且预测超过门槛 → 开多或开空，记下入场价、笔数归零。
7. 以上都不是 → "持有"，目标仓位 = 现仓位（外面看到目标没变就不下单）。

## 4. risk.py：下单前的六道闸门（只有实盘走）

输入：executor 要下的单——标的、方向、名义金额。

0. 跨日了就清账：亏损归零、解除熔断，持仓保留。
1. 磁盘上有急停文件（默认 `logs/KILL`，人手放一个就停）→ 拒单并标记熔断。
2. 之前熔断过、还没人复位 → 拒单，要人工 `reset_halt`。
3. 当日亏损到上限 → 拒单、熔断、记错误日志。
4. 最近一分钟下单数超上限（先扔掉一分钟前的记录）→ 拒单。
5. 单笔名义金额超上限 → 拒单。
6. 成交后持仓（现仓位 + 方向×金额）会超上限 → 拒单。

六道都过 → 放行；成交后 executor 再来登记下单时间和持仓变化。
